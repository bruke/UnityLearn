# 07 - 依赖分析与重复打包

## 学习目标
- 理解 Addressables 如何带依赖 Bundle
- 会用 Analyze 查出重复打包
- 能用共享 Group 降低包体和热更流量

---

![依赖与重复打包](Res/07-依赖分析与重复打包/重复打包.svg)

## 1. 依赖是自动的

Prefab A 引用材质 B，B 引用贴图 C。A 标记为 Addressable 即可，**不必**把 B、C 都勾成 Addressable。打包时 C 会进 **某个** Bundle（通常进 A 所在 Group，或按规则进依赖包）。

若 C 同时被 Group1 的 A 和 Group2 的 D 引用，而 C 自己不是独立 Addressable：

- 默认可能把 C **复制进两个 Bundle**（重复打包）
- 结果：包变大、改 C 要更两个包、运行时可能两份贴图

这是 Addressables 项目最常见的体积问题。

---

## 2. Analyze

```
Addressables Groups → Tools → Analyze
```

常用规则：

| 规则 | 作用 |
|------|------|
| Check Duplicate Bundle Dependencies | 找出打进多个 Bundle 的资产 |
| Check Scene to Addressable Duplicate Dependencies | 场景与 Addressable 重复 |
| Bundle Layout Preview | 预览谁进哪个 Bundle |

对 Duplicate 点 **Fix** 时，工具往往把共享资产 **抽到单独 Group**。Fix 前请提交 Git：自动分组可能不符合你的热更策略，需要再手调。

---

## 3. 共享 Group 做法

1. 建 Group：`Shared_Textures` / `Shared_Materials` / `Shader_Variants`
2. 把重复资产 **显式标成 Addressable**，放进共享组
3. 其它 Prefab 只引用它们，不再内嵌一份

Shader 尤其要集中：

- 散落在各角色 Group 会导致变体膨胀、包体爆炸
- URP 的 Shader 与变体收集仍要在 Graphics / SRP 设置里配合，否则真机粉红

---

## 4. 场景与 Addressable

场景若既在 Build Settings 又是 Addressable，或场景依赖的资源又被其它 Group 打包，容易双份。

建议：

- 热更场景：**只**走 Addressables，不要进 Build Settings 的 Scenes In Build（除启动场景）
- 启动场景保持本地普通场景，里面只有引导代码

---

## 5. 依赖加载链

加载 `char/player` 时，Addressables 先下（或读）依赖 Bundle，再加载资产。所以：

- `GetDownloadSizeAsync("char/player")` 包含依赖
- 进度条会「停很久再动」——可能在下依赖包
- 共享组要 **先于** 业务组到达客户端（Catalog 会按依赖排序下载）

不要把共享组设成 Local、业务组 Remote 却指望共享组永不更新：业务包若依赖「已进首包的旧共享资产」，Content Update 规则会变复杂（第 08 章 Static Group）。
