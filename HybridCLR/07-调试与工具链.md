## 1. 热更代码断点调试

### 1.1 为什么可以断点调试
```
HybridCLR 加载的是标准 DLL + PDB（调试符号）
→ IL2CPP 解释器逐条执行 IL
→ 调试器（VS/Rider）可以映射到源代码行
→ 断点、单步、查看变量全部可用！
```

### 1.2 配置步骤
```
1. 热更 asmdef 生成 PDB 调试符号
   asmdef → Assembly Definition References → 勾选
   "Generate debug info"

2. 加载 DLL 时带上 PDB
   Assembly.Load(bytes, pdbBytes);  // 第二个参数传 PDB

3. VS / Rider → 附加 Unity 进程（Attach to Unity）

4. 在热更代码中打断点
   → 命中断点即可调试
```

### 1.3 加载时带 PDB
```csharp
public Assembly LoadWithPdb(byte[] dllBytes, byte[] pdbBytes)
{
    // pdbBytes 从 AssetBundle 或文件加载
    return Assembly.Load(dllBytes, pdbBytes);
}
```

## 2. 异常定位与处理

### 2.1 热更层抛异常
```
HybridCLR 解释执行时抛出的异常
→ 会在 Console 打印包含 IL 指令和栈帧的信息
→ 栈帧会包含热更方法名（带 PDB 时含行号）
```

### 2.2 结构化异常捕获
```csharp
// AOT 全局异常捕获
public class GlobalExceptionHandler
{
    public static void Install()
    {
        Application.logMessageReceived += OnLogReceived;
    }

    private static void OnLogReceived(string condition, string stackTrace, LogType type)
    {
        if (type == LogType.Exception)
        {
            // 上报异常到服务端
            ReportException(condition, stackTrace);
        }
    }
}
```

### 2.3 热更层 try/catch 建议
```csharp
// 热更层：关键边界加 try/catch
public class BattleSystem
{
    public void Update(float dt)
    {
        try
        {
            // 战斗主逻辑
            UpdateCombatants(dt);
        }
        catch (System.Exception e)
        {
            // 记录但不崩溃
            Debug.LogError($"Battle update failed: {e}");
            // 可上报/回滚战斗状态
        }
    }
}
```

## 3. HybridCLR 提供的诊断工具

### 3.1 编译日志
```
菜单 → HybridCLR → 编译日志
  ├─ 查看热更 DLL 编译是否成功
  ├─ 查看补充元数据生成结果
  └─ 检查程序集配置
```

### 3.2 命令行构建（CI 集成）
```csharp
using HybridCLR.Editor;

    }

```

## 4. 热更开发工作流

```
日常开发（编辑器）:
  直接运行 → 使用源码程序集（HybridCLR 自动用 Editor 程序集）
  → 无需编译 DLL → 热更代码像普通 C# 一样调试

热更联调（真机）:
  1. 编译热更 DLL + PDB
  2. 打包资源（DLL 进 AssetBundle）
  3. 部署到本地服务器
  4. 真机运行 → 加载热更 DLL → 断点调试

发布流程:
  1. 编译 → 生成 DLL + 元数据
  2. 打包资源 → 上传服务器
  3. 验证版本信息
```

## 5. 真机调试技巧

### 5.1 真机上的问题
```
真机（IL2CPP）与编辑器（Mono）行为可能有差异
  ├─ 反射结果可能不同
  ├─ 泛型行为可能不同
  └─ 性能差异明显
```

### 5.2 真机日志
```csharp
// 使用统一的日志系统，方便真机排查
public static class HotfixLogger
{
    public static void Log(string module, string msg)
    {
        Debug.Log($"[HotFix:{module}] {msg}");
    }

    public static void LogError(string module, string msg)
    {
        Debug.LogError($"[HotFix:{module}] {msg}");
    }
}
```

### 5.3 真机 dump / 崩溃排查
```
Android: logcat 抓取
  adb logcat -s Unity

iOS: Xcode Console / Instruments
  崩溃符号化：上传 symbol 文件
```
