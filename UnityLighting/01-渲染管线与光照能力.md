# 01 - 渲染管线与光照能力

## 学习目标
- 在空场景里把 URP 接到可预览状态，并确认颜色空间与 HDR
- 分清内置渲染管线（Built-in）、通用渲染管线（URP）、高清渲染管线（HDRP）的光照能力边界
- 能解释前向（Forward）、前向+（Forward+）、延迟（Deferred）对灯光数量和移动端的影响
- 知道菜单名称会随 Unity / 包版本变化，以窗口标题和文档为准，不背死路径

本专题以 **URP** 为主。Built-in、HDRP 只作对照。Shader 数学见 [光照模型与阴影](/UnityShader/04-光照模型与阴影)，管线阶段见 [基础概念与渲染管线](/UnityShader/01-基础概念与渲染管线)。全局光照落地从下一篇 [实时、烘焙与混合光照](/UnityLighting/02-实时烘焙与混合光照) 开始。

---

## 1. 先做：空项目接到 URP 能亮起来

下面按 **Package Manager 安装 URP** 的常见路径写。Unity 6 模板若已带 URP，可跳过安装，从 1.2 核对资源。

### 1.1 安装与指定管线资源

1. `Window → Package Manager`，在 Unity Registry 搜索 **Universal RP**（包名 `com.unity.render-pipelines.universal`）。记下版本：URP 12（约 2021.2+）、14（约 2022.2+）、17（Unity 6 常见）能力不同。
2. 在 Project 中创建管线资源：`Create → Rendering → URP Asset (with Universal Renderer)`。不同版本可能拆成「URP Asset」+「Renderer」两个资源，名称以右键菜单为准。
3. `Edit → Project Settings → Graphics`，把 **Scriptable Render Pipeline Settings**（或 **Default Render Pipeline**）指到刚创建的 URP Asset。
4. 同一窗口组里的 **Quality**：每个质量等级可以挂不同 URP Asset。移动端常用「低配 Asset 关 HDR、关额外灯光、阴影距离短」。

Built-in 工程升级时，官方提供 **Render Pipeline Converter**（菜单常在 `Window → Rendering` 下，名称随版本为 *Render Pipeline Converter* 或 *Built-in to URP Converter*）。材质、灯光类型、后处理会批量改，转换后必须进 Play 和真机各看一遍。

### 1.2 确认颜色空间与摄像机

1. `Edit → Project Settings → Player → Other Settings → Color Space`：URP / HDRP 项目应使用 **线性（Linear）**。Gamma 能跑，但 PBR 与烘焙结果会偏「灰脏或过曝」。
2. 选中主摄像机：URP 下 **渲染路径不在 Camera 上选**（那是 Built-in 的习惯）。URP 看 URP Asset / Renderer 的 **Rendering Path**。
3. 摄像机 **HDR** 勾选需与 URP Asset 的 HDR 一致，否则 Tonemap 无输入。后处理一般走 **Volume**（全局或局部），组件名在 URP 7+ 已不是 Built-in 的 `Post Process Layer`。

### 1.3 最小灯光检查

场景放一盏 **Directional Light**，一个默认材质立方体。Play 下应看到漫反射明暗。若全粉：Shader 不是 URP 变体，或 Graphics 未挂 URP Asset。若全黑：没灯、Intensity 为 0，或 Volume 曝光拉到极限。

## 2. 原理：管线决定「灯能怎么算」

渲染管线规定：几何如何提交、灯光如何收集、阴影如何采样、是否写入 G-Buffer。光照模型（Lambert、PBR）可以相同，但 **额外灯光数量、阴影图集、延迟 G-Buffer、体积雾入口** 都绑在管线上。

| 管线 | 典型定位 | 颜色空间 | 光照与 GI 要点 |
|------|----------|----------|----------------|
| Built-in | 老项目、插件未迁 | Gamma/Linear 皆可见 | 摄像机选 Forward/Deferred；曾有 Enlighten 实时 GI；新功能少 |
| URP | 手游、主机、跨平台默认 | 强烈建议 Linear | 主光 + 额外光有上限；混合光照、Lightmap、Light Probe 成熟；Unity 6 另有自适应探针体积（APV） |
| HDRP | 高配 PC / 主机写实 | 强制 Linear，HDR 为常态 | 物理单位灯光、体积云雾、屏幕空间 GI / RT 等；移动端基本不考虑 |

不要把「能出图」当成「能力相同」。同一套混合光照模式在三套管线里的阴影遮罩精度、额外光阴影、探针系统都不一样。

## 3. 渲染路径（Rendering Path）

### 3.1 前向（Forward）

每个物体对「主光 + 若干额外光」在片元里累加。实现简单、半透明友好、移动端默认。代价：灯光一多，同一物体多次光照计算；额外光阴影在 URP 里常受限（看 Renderer 的 Additional Lights 与 Shadow 开关）。

### 3.2 前向+（Forward+ / Clustered）

URP 14+（约 Unity 2022.2）起在 URP Asset 的 Rendering Path 中可选（名称可能是 *Forward+*）。用屏幕/簇划分灯光列表，**可见灯光数量远高于经典 Forward**，仍走前向着色，半透明比 Deferred 省心。中高端移动端和 PC 中低配常用。低端机要测 CPU 裁灯光与带宽。

### 3.3 延迟（Deferred）

先写 G-Buffer，再按光覆盖范围着色。大量本地光时 GPU 更稳，但对 MRT、带宽、半透明（通常仍 Forward）要求高。Built-in 在 **Camera → Rendering Path** 选择。URP 12+ 提供 Deferred，需检查 Renderer 是否包含 Deferred 相关 Pass，以及平台是否支持所需图形 API。HDRP 默认偏延迟，个别材质可走 Forward。

对照备忘：

| 路径 | 多灯 | 半透明 | 移动端 |
|------|------|--------|--------|
| Forward | 受额外光上限约束 | 自然 | 默认、好控 |
| Forward+ | 明显放宽 | 仍前向 | 中端以上优先评估 |
| Deferred | 本地光多时有优势 | 额外路径 | 中高端；注意带宽与 G-Buffer 格式 |

## 4. 线性颜色空间（Linear）与高动态范围（HDR）

### 4.1 为什么烘焙和 PBR 要 Linear

灯光衰减、反弹、材质 albedo 的混合是线性运算。Gamma 空间下「两次一半的光」不等于「一半的显示亮度」，烘焙间接光和实时高光都会漂。导入贴图时 sRGB（颜色）与 Linear（数据：法线、遮罩）不要勾错，否则 Lightmap 与探针会「脏」。

### 4.2 HDR 与色调映射（Tonemapping）

HDR 让场景亮度可以超过 1，再由 Volume 里的 Tonemap（ACES 等）压到显示器。URP Asset 上关闭 HDR 后，再强的灯也会在着色阶段被钳制，烘焙间接光和自发光爆光都会变假。移动端可：**线性 + HDR 开、Bloom 关或阈值提高、额外光阴影关**，比整条退回 Gamma 更可控。

HDRP 默认按物理单位（Lux 等）工作，不要把 Built-in 的 Intensity=1 太阳光数值原样搬过去。

## 5. 编辑器里和光照相关的开关（URP Asset）

打开 URP Asset，按分组核对（分组标题随包版本会改，认字段不认菜单位置）：

| 字段（常见英文） | 作用 |
|------------------|------|
| HDR | 是否允许摄像机 HDR 路径 |
| MSAA | 前向抗锯齿；Deferred 时常不可用或含义不同 |
| Main Light / Additional Lights | Per Pixel 还是 Disabled；额外光 Per Object Limit |
| Shadow | 主阴影分辨率、距离、级联；额外光阴影 |
| Rendering Path | Forward / Forward+ / Deferred |
| Opaque / Transparent Downsampling | 影响深度与扭曲类效果，间接影响体积光类 Feature |

Quality 里可以让「Ultra 用 Deferred + 高阴影，Low 用 Forward + 无额外光阴影」。不要只改场景灯却忘了当前 Quality 挂的是另一份 Asset。

## 6. 常见项目方案

| 项目类型 | 建议 |
|----------|------|
| 手游主包 | URP + Linear + Forward 或条件 Forward+；主光实时，静态用混合光照 + Lightmap |
| 主机 / PC 中端 | URP Forward+ 或 Deferred；混合光照 + 探针；后处理 Volume 统一 |
| 写实高配 | HDRP；灯光走物理单位；GI 用 HDRP 提供的探针/屏幕空间方案，而不是抄 URP 菜单 |
| 维护老包 | 可暂留 Built-in Linear；新关卡不要再上 Enlighten 实时 GI，迁移时一次切 URP |

灯光数量：主方向光 1 盏负责太阳/月亮；室内补光优先烘焙或探针，而不是堆 20 盏实时点光。

## 7. 性能与移动端

- 额外光 Per Object Limit 在 Forward 下直接乘在片元成本上；角色过走廊时用 Light Probe，不要靠点光「照亮动态物体」。
- 阴影距离和级联对带宽极敏感；移动端主光阴影 1～2 级联、距离按玩法裁。
- Deferred 的 G-Buffer 在 TBDR 手机上可能更亏，不要只看 PC 帧率。
- 线性 + HDR 本身不是大开销；贵的是高分辨率阴影、多灯阴影、全屏后处理。
- 真机务必关 Development Player 对比；编辑器 Game 视图开 HDR 与真机 LDR 显示器观感会差一截。

## 8. 常见故障排查

| 现象 | 先查 |
|------|------|
| 材质粉红 | 不是 URP Shader；Graphics 未指定 URP Asset；剥离了变体 |
| 场景极暗或极亮 | Color Space 与贴图 sRGB；Volume Exposure；灯 Intensity 单位（HDRP） |
| Camera 找不到 Rendering Path | URP 请改 Asset，不是 Camera |
| 编辑器亮、真机暗 | Quality 用了另一份 URP Asset；移动端关了 HDR 却仍用 ACES 预设 |
| 额外灯不亮 | Additional Lights 被 Disabled；Forward 超 Limit；层剔除 |
| 切 Deferred 黑屏 | 平台/API 不支持；Renderer 未含 Deferred；后处理不兼容 |
| Converter 后灯光全错 | 混合模式、阴影类型、Intensity 被转换规则改过，按灯逐盏对 |
