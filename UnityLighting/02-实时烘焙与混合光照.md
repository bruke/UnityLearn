# 02 - 实时、烘焙与混合光照

## 学习目标
- 会把灯的模式设为实时（Realtime）、烘焙（Baked）、混合（Mixed），并看懂 Play 与烘焙结果的差别
- 能在 Lighting Settings 里选择混合模式：烘焙间接（Baked Indirect）、阴影遮罩（Shadowmask）、减去法（Subtractive）
- 正确给静态物体打 **Contribute GI**，避免「灯是 Mixed、场景却全是实时阴影」
- 分清 URP 能做什么、Built-in 老项目的 Enlighten 实时 GI 不要照搬

管线与 HDR 前提见 [渲染管线与光照能力](/UnityLighting/01-渲染管线与光照能力)。贴图参数与漏光见 [光照贴图（Lightmap）](/UnityLighting/03-光照贴图Lightmap)，动态物体接光见 [光照探针（Light Probe）](/UnityLighting/04-光照探针LightProbe)。

---

## 1. 先做：三盏灯对比一次

用 URP 场景：地面、墙、一个未勾静态的立方体（当角色）、一盏 Directional Light。

### 1.1 打开光照窗口与 Lighting Settings

1. `Window → Rendering → Lighting`（2019.3 之后常见路径；更老版本可能是 `Window → Lighting → Settings`）。窗口内标签名称常变，认 **Scene / Environment / Realtime GI** 这类分组。
2. 若提示创建 **Lighting Settings** 资源：创建并保存到 `Assets`，例如 `Assets/Settings/MainLighting.settings`。从 Unity 2019.2 起，烘焙参数在资源上，可多场景共享。不要只改当前场景却以为所有场景已统一。
3. Environment：指定 Skybox 或环境色。环境光会进入烘焙间接光；URP 下环境采样也影响实时反射与探针。

### 1.2 三种 Mode 各 Bake 一次

选中方向光，Inspector → **Mode**：

| Mode | 操作 | 你应看到 |
|------|------|----------|
| Realtime | 不依赖烘焙；可把 Lighting 窗口里 Baked GI 先关掉对比 | 静态/动态都吃实时光和实时阴影（若开了 Shadow） |
| Baked | Generate Lighting | 静态物体明暗进 Lightmap；动态物体几乎不吃这盏灯的直接光（靠探针吃间接） |
| Mixed | 选一种 Lighting Mode 再 Generate | 动态吃实时直射；静态直射/间接/阴影按模式拆分 |

第一次请用 **Baked Indirect**（见第 3 节），主光 Shadow Type 用 Soft Shadow。Bake 完成后：移动「角色」立方体，地面上应有实时阴影；墙角间接光应已经印在 Lightmap 上，不随角色移动而改变。

## 2. 原理：运行时算什么、贴图存什么

```
最终 ≈ 直接光 + 阴影 + 间接光（反弹）+ 环境
```

- **Realtime**：直接光与阴影每帧算。间接光若没有实时 GI 方案，就只剩环境/探针/屏幕空间近似。URP 传统没有 Built-in 那套 Enlighten **Realtime GI**；Unity 6 的自适应探针体积（APV）是另一条产品线，不在本篇展开。
- **Baked**：这盏灯在运行时不再作为实时光源参与（或贡献为 0）。直射、阴影、间接都进 Lightmap / Light Probe。移动物体不会在墙上留下这盏灯的实时影子。
- **Mixed**：运行时保留灯光，用来照亮动态物体并（按模式）打实时阴影；静态侧把间接、甚至阴影烘焙掉，降低 Overdraw 与阴影图集压力。

**Contribute GI**（老版本勾选 Static 里的 Lightmap Static / 现多为 Static 下拉中的 Contribute GI，Mesh Renderer 上还有 Contribute Global Illumination）表示：这物体 **参与** 烘焙（投射阴影到 Lightmap、接收 Lightmap）。动态角色一般 **不勾**，改用 Light Probe 接收间接光。

Renderer 上 **Receive Global Illumination**（名称随版本可能是 Lightmaps / Light Probes 下拉）：

- Lightmaps：必须有合法 UV2，且物体被当成静态 GI 贡献者。
- Light Probes：运行时插值探针，见 [04](/UnityLighting/04-光照探针LightProbe)。

## 3. 混合光照模式（Lighting Mode）

在 Lighting Settings 的 **Mixed Lighting → Lighting Mode**（或 Lighting 窗口 Mixed 分组）选择。改模式必须 **重新 Generate Lighting**。

### 3.1 烘焙间接（Baked Indirect）

- 静态：实时直射 + 实时阴影 + **烘焙间接**。
- 动态：实时直射 + 实时阴影；间接来自探针。
- 观感最好理解：和「全实时」接近，只是把反弹预存起来。
- 代价：静态物体仍吃实时阴影，阴影距离内成本和全实时接近。适合主机、对阴影质量要求高的室内。

### 3.2 阴影遮罩（Shadowmask）与距离阴影遮罩（Distance Shadowmask）

- 静态对静态的阴影可进 **Shadowmask** 贴图（与 Lightmap 配套）。
- 动态物体仍用实时阴影。
- Quality 设置里常有 **Shadowmask Mode**：*Shadowmask*（远处也用遮罩）与 *Distance Shadowmask*（阴影距离内实时、距离外遮罩）。字段在 `Project Settings → Quality`，URP 项目同样生效，名称以当前版本 Quality 面板为准。
- 适合：大世界、需要远景静态阴影但不想全距离实时级联。

注意：Shadowmask 通道数量有限（常见最多 4 盏重叠的 Mixed 灯）。第五盏 Mixed 灯的遮罩会打架，表现为静态阴影丢失或闪。

### 3.3 减去法（Subtractive）

- 静态：直射、阴影、间接全部烘焙，运行时不再用实时主影去画静态网格。
- 动态：实时光照；为了让角色阴影「印」在已经烘焙亮的地面上，用实时阴影去 **减弱** Lightmap（subtract）。
- 移动端最省，但角色阴影发脏、与烘焙接缝明显，且对主光方向变化几乎无法实时改静态明暗。
- 适合：低端 Android、灯方向固定的卡通/中景。

对照：

| 模式 | 静态阴影 | 动态阴影 | 移动端 |
|------|----------|----------|--------|
| Baked Indirect | 实时 | 实时 | 偏贵 |
| Shadowmask | 遮罩（远景可关实时） | 实时 | 中等 |
| Subtractive | 全烘焙 | 从 Lightmap 减去 | 最便宜 |

HDRP 的混合与阴影策略更偏物理管线，不要用 URP 的 Subtractive 菜单去对标 HDRP 项目。

## 4. 静态标记怎么打（避免错打）

在 Hierarchy 选物体 → Inspector 右上 **Static** 下拉（不要只勾总开关就完）：

| 标志（常见名） | 光照相关 |
|----------------|----------|
| Contribute GI | 参与 Lightmap / 烘焙可见性 |
| Batching Static | 与 GI 无关，但是静态合批常和场景网格一起开 |
| Occluder / Occludee | 遮挡剔除，不是 GI |
| Reflection Probe Static | 进反射探针烘培 |

Mesh Renderer：

1. **Contribute Global Illumination** 勾上。
2. **Receive Global Illumination = Lightmaps**。
3. **Scale In Lightmap** 默认 1；小道具可降到 0.5 省 texel。
4. 若物体要动（门、电梯）：不要 Contribute GI，或拆成「静态框 + 动态扇」。

地形 Terrain 有独立 Lightmap 参数；草/细节层通常不进 Lightmap，靠探针或实时。

## 5. Lighting Settings 里先动的参数

| 参数（常见英文） | 说明 |
|------------------|------|
| Lightmapper | Progressive CPU / Progressive GPU。GPU 快，大场景显存不够会失败或回退 |
| Lighting Mode | 上一节三种 Mixed |
| Direct / Indirect / Environment Samples | 采样越高越干净、越慢 |
| Lightmap Resolution | 每单位 texel，详见 [03](/UnityLighting/03-光照贴图Lightmap) |
| Max Lightmap Size | 512/1024/2048；移动端常 1024 |
| Compress Lightmaps | 移动端开；注意块状伪影 |
| Directional Mode | Directional 保留主导光方向，PBR 高光更稳；Non-Directional 更省 |
| Ambient Occlusion | 烘焙 AO，别和 SSAO 叠太狠 |
| Albedo Boost / Indirect Intensity | 间接过亮先查这个，再查环境 Skybox 强度 |

**Generate Lighting** 与 Auto Generate：迭代期可 Auto，出包前关掉 Auto，固定结果进版本库（Lightmap 贴图、Lighting Data Asset）。多人协作时 Lighting Data 冲突很常见，约定「谁烘场景谁提交」。

## 6. 常见项目方案

| 方案 | 灯怎么配 |
|------|----------|
| 手游日夜固定 | 主光 Mixed + Subtractive 或 Shadowmask；点光室内 Baked；角色探针 |
| 主机室内 | 主光 Mixed + Baked Indirect；补光 Baked；少量 Mixed 聚光（注意 4 盏遮罩） |
| 可破坏/可移家具 | 家具不 Contribute GI；靠探针+实时或局部实时灯 |
| 只有动态时间（昼夜） | 纯实时或 APV/屏幕空间方案；**不要**指望一份 Lightmap 覆盖多时段，除非多套烘焙切换 |

Built-in 老项目若仍开 **Realtime GI（Enlighten）**：URP 不能直接迁移该开关。迁移时改 Mixed + 探针，或评估 Unity 6 APV。

---

## 7. 性能与移动端

- Mixed 不等于省：Baked Indirect 的实时阴影成本仍在。
- Subtractive 省阴影，但 Lightmap 张数、解码、双线性采样仍占带宽。
- 点光尽量 Baked；实时点光阴影在 URP 额外光里很贵。
- 不要把整座城的小石子都 Contribute GI。
- 打 Android 前在目标 Quality 下 Bake：编辑器 Ultra 的 Shadowmask 与真机 Low 的 Distance 不一致会导致「编辑器有影、真机没影」。

## 8. 常见故障排查

| 现象 | 先查 |
|------|------|
| Bake 完静态仍全黑 | 未 Contribute GI；Mode 是 Realtime 却以为烘了；没 Generate |
| 动态角色发黑 | 没有 Light Probe；Receive GI 误设 Lightmaps |
| Mixed 但静态没有实时影 | 当前是 Subtractive 或 Shadowmask 且距离外；灯没开 Shadow |
| 静态阴影闪、丢 | Mixed 灯超过 Shadowmask 通道；两盏灯重叠过多 |
| 改灯没变化 | Auto Generate 关了；烘的是另一份 Lighting Settings |
| GPU Lightmapper 失败 | 降分辨率、关其他占显存进程、改 CPU |
| 场景间亮度跳 | 未共享 Lighting Settings；环境 Skybox 不同 |
