# 12 - 渲染优化与工程实践

## 学习目标

- 能按「先看清瓶颈，再改批次 / 填充 / 光照预算」的顺序做优化，而不是先关特效碰运气
- 掌握 LOD Group、遮挡剔除（Occlusion Culling）、SRP Batcher、GPU Instancing、静态合批（Static Batching）各自适用面
- 能用 Frame Debugger、Profiler、RenderDoc 定位问题，并按移动端 / PC 基线做发布检查

---

## 1. 原理：瓶颈分三类

| 类型 | 症状 | 先动什么 |
|------|------|----------|
| CPU 提交 | SetPass / Draw Call 高，游戏线程忙 | 合批、减少材质变体、裁剪 |
| GPU 填充（Fill） | 分辨率一升就掉帧，Overdraw 高 | 半透明、全屏效果、阴影分辨率 |
| GPU 几何 / 带宽 | 三角过多、贴图过大 | LOD、压缩、实例化 |

光照相关成本往往同时打在三类上：每盏实时灯增加 SetPass 与片元照明；阴影贴图增加 Draw；屏幕空间效果增加全屏填充。管线能力见 [渲染管线与光照能力](/UnityLighting/01-渲染管线与光照能力)，着色器侧见 [Shader 性能优化](/UnityShader/07-Shader性能优化)。

## 2. 编辑器配置 / 落地步骤

### 2.1 LOD Group（细节层次）

1. 为网格准备 LOD0 / LOD1 / LOD2（三角数大约按 100% / 40% / 15% 量级递减，按美术规范即可）。
2. 父物体加 **LOD Group**，拖入子网格，调屏幕相对高度（Relative Height）切换点。
3. 远处用更简单材质：去掉法线、视差、额外灯光关键词。
4. 广告牌（Billboard）只给很远的树/人群。交叉淡入（Cross Fade）在移动端慎开。

### 2.2 遮挡剔除（Occlusion Culling）

1. Window → Rendering → Occlusion Culling（名称随版本可能微调）。
2. 静态大遮挡物勾选 Occluder Static，被挡物勾 Occludee Static（具体复选框在 Static 下拉里，以当前编辑器为准）。
3. Bake 遮挡数据，Play 模式下用 Visualization 看单元格是否合理。
4. 室内、巷道收益高；大旷野几乎无遮挡，不要指望它替代 LOD。
5. 动态物体默认不挡别人；门开关类要用专门方案，不能只靠一份静态 bake。

### 2.3 批处理与 GPU Resident Drawer：别叠着用错

| 技术 | 条件 | 优点 | 陷阱 |
|------|------|------|------|
| SRP Batcher | 同 Shader 变体、CBUFFER 布局合规 | URP 默认主力，减 SetPass | 材质属性进错 Buffer 会静默失败 |
| GPU Instancing | 同 Mesh + 同 Material | 大量重复物 | 不同材质合不了；要自己传实例数据 |
| Static Batching | 静态标记、网格合并 | 降低提交 | 内存复制网格；动态物体无效；破坏合批的缩放/材质差异 |
| GPU Resident Drawer | Unity 6 URP、Forward+、兼容的 Renderer | 通过 BatchRendererGroup 自动实例化，可配 GPU 遮挡剔除 | 有平台、Shader 与 Renderer 限制；不兼容 Static Batching |

URP 优先保持 **SRP Batcher 开启**。Unity 6 新项目应先评估
**GPU Resident Drawer**；启用它时关闭 Static Batching，因为两者不兼容。
没有使用 GPU Resident Drawer 的旧版本或不兼容平台，才按项目验证结果选择
Static Batching。重复植被、子弹、网格贴花的手动实例化见
[GPU Instancing 与程序化渲染](/UnityShader/12-GPUInstancing与程序化渲染)。

检查 SRP Batcher 是否生效：Frame Debugger 里合批信息 / Player 设置中 SRP Batcher 统计。不合批时先查关键字（雾、灯光、阴影、贴花）是否把变体打散。

Unity 6 中启用 GPU Resident Drawer 的典型前提是：URP Asset 开 SRP Batcher，
Renderer 使用 Forward+，并按项目保留 BatchRendererGroup 所需 Shader 变体。
GPU Occlusion 还要求使用 Render Graph 路径。字段名称以当前 Unity 6 小版本为准。

### 2.4 阴影与灯光预算

1. 主平行光：阴影距离（Shadow Distance）、级联（Cascade）数量、分辨率按档位表锁死。见 [阴影系统与 Shadowmask](/UnityLighting/07-阴影系统与Shadowmask)。
2. 额外灯（Additional Lights）：移动端 Per Object Limit 要小；能烘焙的不要实时。
3. Mixed + Shadowmask 给静态影，动态物体用实时短距离阴影。
4. 点光/聚光阴影极贵，移动端默认关。
5. 屏幕空间增强只留 SSAO 一档，组合见 [屏幕空间光照效果](/UnityLighting/11-屏幕空间光照效果)。

### 2.5 Overdraw（过度绘制）

半透明、粒子、全屏Blit、多层贴花会在同一像素反复着色。Scene 视图绘制模式选 Overdraw（若当前版本提供）或用 RenderDoc 看 Pass。粒子改不透明/Alpha Test、减全屏效果、贴花减通道，比「把分辨率砍一半」更对症。

## 3. 关键参数与推荐基线

下列数字是**工程起点**，最终以目标机 Profiler 为准。

| 项目 | 移动端基线 | PC 基线 |
|------|------------|---------|
| 分辨率 | 720p～1080p + 动态分辨率 | 原生；4K 要单独档 |
| 主光阴影距离 | 20～40 m | 80～150 m 再谈 |
| 阴影级联 | 1～2 | 2～4 |
| 额外实时灯 | 每物体 0～1，尽量无阴影 | 数盏，阴影严格选 |
| SSAO | 半分辨率或关 | 开，控制半径 |
| SSR / SSGI / 体积雾 | 关 | 高档才开 |
| LOD 层 | 3 层，切换偏近 | 可更晚切 |
| 批处理 | SRP Batcher；Unity 6 评估 GPU Resident Drawer | SRP Batcher + GPU Resident Drawer；未使用时再评估静态合批 |
| 贴花 | 网格贴花 / 少 Screen Space | DBuffer 可接受 |

URP Asset 的 Quality 分级应对齐项目 Quality Settings，避免「低品质档仍引用高配 Renderer Feature 列表」。

## 4. 工具怎么用

### 4.1 Frame Debugger

`Window → Analysis → Frame Debugger`。逐 Draw 看：是谁、什么 Shader、为什么没合批、阴影 Pass 画了几遍、全屏 Effect 插在哪。优化前后保存同一相机机位对比 Draw 数。

### 4.2 Profiler

`Window → Analysis → Profiler`。看 CPU `Rendering` / `Shadows`、GPU 模块（需支持的平台与 Graphics Jobs 设置）。同时看内存里的 RenderTexture、阴影贴图尺寸。移动端务必 **真机** 连 Profiler，不要只看编辑器 Game 视图。

### 4.3 RenderDoc

抓一帧：看 Overdraw、带宽、每个 Pass 的 RT 格式（是否不必要的 HDR、MSAA）。定位「SSAO 半分辨率却仍很贵」这类问题比看 FPS 数字快。平台侧还有 Xcode GPU、Snapdragon Profiler 等，见 Shader 篇工具表。

## 5. 常见问题

| 现象 | 原因与处理 |
|------|------------|
| SRP Batcher 统计为 0 | 自定义 Shader 的 UnityPerMaterial 不规范；或多关键字拆变体 |
| 静态合批后内存暴涨 | 网格被复制。大世界改 Instancing / 运行时合批策略 |
| 开 Occlusion 更卡 | Bake 过碎或野外无遮挡。减小体积精度或关掉 |
| LOD 切换「弹出」 | 屏幕高度阈值太陡；或 LOD1 材质更亮。加滞回、统一曝光 |
| 阴影占半帧 | 距离过远、级联过多、额外灯阴影。先砍距离 |
| 半透明一加就掉帧 | Overdraw。改粒子排序、减少全屏叠层 |
| 编辑器 60、真机 20 | 以真机为准；注意发热降频 |
| Instancing 不生效 | 材质没开 Enable GPU Instancing，或 Mesh/Material 不一致 |

## 6. 发布检查表

- [ ] Quality 档与 URP Renderer / 特性列表一一对应（低档无 SSR、无额外阴影灯）
- [ ] 线性颜色空间、HDR、MSAA/TAA 选择已按平台定稿
- [ ] 主光阴影距离、级联、分辨率有数字，不是「默认」
- [ ] 实时灯与点光阴影有上限；能烘焙的静态光已烘焙
- [ ] Fog / 天空 / 探针 / 贴花已按档位关掉或降级
- [ ] LOD、遮挡烘焙（若使用）打进包，且场景改网格后重新 Bake
- [ ] SRP Batcher 开启；GPU Resident Drawer 与 Static Batching 没有同时启用；关键 Shader 变体已预热 / 剥离
- [ ] 目标机 Frame Debugger + Profiler 跑过主场景与战斗高峰
- [ ] 粒子与 UI 的 Overdraw 看过；全屏后处理 Pass 数可知
- [ ] 包体：贴图压缩、网格压缩、未引用 Renderer Feature 已删

资源侧内存与包体另见资源管理专题；本篇只锁**渲染提交与 GPU 帧时间**。

---

## 7. 学习检查点

- [ ] 能判断当前卡在 CPU 批次、GPU 填充还是阴影 Pass
- [ ] 能正确选用 LOD、遮挡剔除、SRP Batcher、Instancing、静态合批，并说出不能混用的理由
- [ ] 能给出移动端 / PC 的灯光与屏幕空间效果预算
- [ ] 能用 Frame Debugger 指出一次未合批，用 Profiler/RenderDoc 指出一次昂贵全屏 Pass
- [ ] 能在发版前按检查表过一遍，而不是只看编辑器 FPS
